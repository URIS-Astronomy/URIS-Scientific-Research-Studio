# Engineering RC feature matrix

| Workflow | Implementation and validation boundary |
|---|---|
| Camera discovery and capabilities | UDP discovery and TCP reconnect. Camera2 reports camera and physical IDs, sensor size, capture formats, exposure/ISO/focus limits, zoom, AWB, stabilization and supported video tuples. The Vivo main lens and real stream combinations require device confirmation. |
| Android operation | Live Camera2 preview, local exposure/focus/crop controls, JPEG/RAW/DNG capture, native JPEG burst and video. Screen-on flag, wake lock, exit confirmation, local luma histogram, preview frame count, battery temperature and storage telemetry. Session planning, EAA and advanced analysis run on the PC. |
| Stills and Moon/Solar | Native JPEG burst uses one Camera2 capture-burst submission for 2–16 images and is available when BURST_CAPTURE is reported. JPEG, RAW and combined stills use the configured camera outputs. Moon/Solar profiles, crop, highlight clipping and focus peaking are exposed in the dashboard. RAW bursts use sequential capture. |
| Planetary video | Camera2 standard or constrained high-speed recording to H.264 MP4. Stop by time or Camera2 frame-start threshold. The dashboard shows Camera2 starts and loss events, the finalized MP4 sample count, and cadence gaps estimated from adjacent presentation timestamps. MediaCodec output timestamps are matched to Camera2 sensor timestamps inside the recording interval to count missing encoder outputs when the clocks align. The dashboard reports when alignment is unavailable. High-speed mode uses automatic settings and local phone preview. |
| Planetary review | Optional worker scores up to 240 uniformly sampled decoded video frames by central Laplacian energy and saves up to five ranked full-resolution PNGs. The dashboard and session journal report the sample count and scores. |
| Deep sky | Light, dark, flat and bias frame types, exposure controls, interval sequencing, and manual-light integration estimate. The Sequence Manager resumes from the last recorded exposure in the same session after a restart, restores settings, and rebuilds a live stack from received lights. Sequence requests keep a stable capture ID and Android persists a completion receipt to replay saved files after either app restarts. If the phone stops before finalizing the receipt, recovery retries that exposure with the original ID. |
| Calibrated live stack | JPEG or classic uncompressed 16-bit Bayer DNG preview. Build mean bias, dark and normalized flat masters from selected capture sessions, apply them to incoming preview pixels, register with bounded translation and small rotation, reject weak matches, update accepted/rejected counts and histogram, and export PNG. DNG masters and lights use a bounded debayered display preview. Full-resolution linear RAW output is handled separately through optional Siril. Vivo DNG layout compatibility requires a real capture. |
| Focus and histogram | Background-subtracted central stellar HFR and Gaussian-equivalent FWHM with faint, clipped and non-stellar rejection. Focus history, centered magnification, clipping warning overlay, stack/live histogram, and relative lunar/planetary contrast. Pixel overlays run in a worker. |
| Session manager | Lists journals under Pictures / TOD Astro Photography / date / target / session. Shows verified progress and received files and supports resuming interrupted sequences. Journals include capture settings, time, telemetry, checksums and reconnect events. |
| Siril | Optional CLI staging and generated homogeneous conversion, calibration/master creation, debayering, registration and stacking script. The dashboard reports progress and checks the expected output. End-to-end execution with a supported Siril installation remains unverified. |
| Interoperability | Camera transport, journaling, and image processing remain separate from the web dashboard. ASCOM Alpaca, mounts, guiding, and plate solving are future integrations from the original requirements. |
